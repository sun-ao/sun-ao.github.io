先搞懂：Docker 到底是什么（大白话）
#

装之前先花两分钟弄明白，否则装完也不知道能干嘛。

想象你要部署一个网站，它需要一套特定的运行环境（某个版本的系统 + 一堆依赖库）。传统做法是在电脑上装这装那，搞完这台机器就"脏"了，换个环境又得重来。

Docker 的做法：把"应用 + 它需要的整套环境"打包成一个集装箱（镜像 image），这个箱子搬到任何装了 Docker 的机器上都能原样跑起来，不挑环境、不互相干扰。跑起来的箱子实例叫容器（container）。

几个词先认识：

词大白话类比
镜像 image一个只读的"安装包模板"装系统的 ISO 镜像
容器 container镜像跑起来的实例装好系统在运行的电脑
Dockerfile描述"怎么造镜像"的清单菜谱
Docker Hub官方的镜像下载市场应用商店
docker compose用一个文件编排多个容器一次启动一整套服务

Docker Desktop 是 Docker 官方出的桌面软件：在 Windows / Mac 上帮你把这套引擎跑起来，还带一个图形界面管理容器。它内部靠 WSL2（Windows 的 Linux 子系统）跑一个轻量 Linux 环境——这就是为什么 Windows 上装它要先开 WSL2。

一句话：Docker Desktop 让你在 Windows 上也能方便用 Docker，跑数据库、跑测试环境、装各种"一键启动"的开源服务都靠它。

01 ｜ 前置一：先确认授权（免费还是要付费）
#

🟡 方案整理 · 待实机验证

为什么：Docker Desktop 不是无条件免费的。这是 2021 年改过的政策，很多老教程没提，公司用错会有合规风险。Docker 引擎本身开源免费，收费的是 Docker Desktop 这个桌面产品。

免费范围（2026 年现行条款）：

  • 个人使用 ✅
  • 教育用途 ✅
  • 非商业的开源项目 ✅
  • 小企业：员工 < 250 人 且年营收 < 1000 万美元 ✅

需要付费订阅的情况：超出上述规模的企业、政府机构、商业用途。价格大致 Pro $9 / Team $15 / Business $24 每人每月（年付）。

算完成：对号入座，确认自己属于免费范围还是付费范围。个人和小团队基本都免费。

我试过的：

  • 安装和下载不要求登录 Docker 账号，授权是在首次启动时接受协议、登录时才校验。
  • 公司机器由 IT 统一管理的话，让他们确认授权，别自己装了再说。
  • 如果公司卡授权、不想付费，跳到文末「免费替代方案」——Podman Desktop / Rancher Desktop 完全免费开源，命令几乎一样。

02 ｜ 前置二：确认系统支持 + 开虚拟化
#

🟡 方案整理 · 待实机验证

为什么：Docker Desktop 靠虚拟机技术跑 Linux 环境，CPU 必须在 BIOS 里开"虚拟化"支持，否则装了也起不来。这是最常见的翻车点。

照抄（三步检查）：

第一步：看 Windows 版本

按 Win + R → 输入 winver → 回车。确认是 Win11 64 位、build 22631（23H2）或更高。Win11 家庭版就能跑 Linux 容器，够用。

第二步：看虚拟化开没开

按 Ctrl + Shift + Esc 打开任务管理器 → 点「性能」→ 点「CPU」→ 看右下角「虚拟化」：

  • 显示「已启用」→ 过关，跳到第三步
  • 显示「已禁用」→ 要重启电脑进 BIOS 开：开机时按 Del 或 F2（不同品牌键不同）进 BIOS，找到 Intel VT-x / AMD-V / SVM / Virtualization Technology 之类的选项，设为 Enabled，保存重启

第三步：看内存

任务管理器 → 性能 → 内存，确认 ≥ 8GB（4GB 是底线但会很卡）。Docker 会分走一部分给 Linux 虚拟机。

算完成：winver 版本合格、任务管理器里虚拟化显示「已启用」、内存 ≥ 8GB。

03 ｜ 前置三：装好 WSL2
#

🟡 方案整理 · 待实机验证

为什么：前面 Ubuntu 篇已经讲过 WSL。Docker Desktop 默认就用 WSL2 作为后端——Windows 上的 Docker 命令，实际是发给 WSL2 里的 Linux 引擎执行。没它不行。

照抄：

右键开始菜单 → 「终端（管理员）」→ 点「是」→ 执行：

wsl --install

装完重启电脑。重启后再确认版本：

wsl --version

看输出里 WSL 版本 ≥ 2.1.5（老版本用 wsl -l -v 看 VERSION 列是 2）。如果装过但版本旧，用 wsl --update 升级。

想更彻底了解 WSL、装 Ubuntu 子系统，看本系列 Ubuntu 篇。这里只装 WSL2 核心就够 Docker 用。

算完成：wsl --version 能正常输出版本号，且 ≥ 2.1.5。

我试过的：wsl --install 在某些机器上会卡在下载，可加 --web-download 重试（wsl --install --web-download），和 Ubuntu 篇 里的解法一致。

04 ｜ 安装 Docker Desktop
#

🟡 方案整理 · 待实机验证

为什么：前置都满足后，安装本身很简单，一路 Next 就行。关键是选对架构、别改后端设置。

照抄：

  1. 打开官网 https://www.docker.com/products/docker-desktop/，点下载（得到 Docker Desktop Installer.exe，约 600MB）
  2. 选对架构：绝大多数 Intel / AMD 电脑下 x64 / AMD64；骁龙 X / Surface 等 ARM 电脑下 ARM64（在「设置 → 系统 → 关于」看"系统类型"确认）
  3. 双击安装包 → 保留默认勾选的「Use WSL 2 instead of Hyper-V」→ 点 Ok → 一路安装
  4. 完成后按提示注销并重新登录（或重启），应用用户组变更
  5. 从开始菜单打开 Docker Desktop → 首次会弹协议 → 读一下点接受；问是否登录 Docker 账号，个人用可以跳过（Skip）
  6. 等右下角托盘的小鲸鱼图标变稳定、主界面左下角显示 “Engine running"（绿色），就装好了

算完成：打开终端执行：

docker --version

输出版本号（如 Docker version 4.x.x）即成功。

我试过的：

  • 安装模式：默认"按用户安装（Per-user）“就够了，不需要管理员权限、装在当前用户目录；只有需要 Windows 容器或集中管理时才选"所有用户（All users）"——那种要管理员权限，且能把 Hyper-V 当后端。个人开发用默认即可。
  • 验证安装包真伪：右键安装包 → 属性 → 数字签名，签名者应是 Docker 官方且签名有效。别从第三方下载站拿"高速版”。
  • 也可以用 winget：winget install --id Docker.DockerDesktop -e，适合习惯命令行的（见 02 篇）。
  • 也可以用 Docker VMM 后端（新版测试特性，更省内存、文件 IO 更好），在设置里切；但默认 WSL2 最稳，新手别折腾。

05 ｜ 配置国内镜像源（国内必做）
#

🟡 方案整理 · 待实机验证

为什么：Docker Hub 在国内访问很慢甚至超时，拉个镜像能等半小时。国内镜像源就是 Docker Hub 的"国内中转站”。但注意：2024–2026 大量老牌镜像站关停了（中科大、网易、Docker 官方中国区都已失效），网上很多教程的配置已经没用。这一节的地址是 2026 年实测可用的，且要接受一个现实：镜像站随时可能失效。

照抄（图形界面配置，最简单）：

  1. 打开 Docker Desktop → 点右上角齿轮图标（Settings）
  2. 左侧菜单选「Docker Engine」
  3. 在右侧 JSON 编辑框里，找到或加上 registry-mirrors 字段，改成下面这样（注意 JSON 格式，别漏逗号）：
{
  "registry-mirrors": [
    "https://dockerproxy.net",
    "https://docker.1ms.run",
    "https://hub.rat.dev",
    "https://docker.m.daocloud.io",
    "https://docker.xuanyuan.me"
  ]
}
  1. 点「Apply & Restart」，等 Docker 重启完成

也可以直接改配置文件：%UserProfile%\.docker\daemon.json，写入同样的内容再重启 Docker Desktop。效果一样。

算完成：重启后执行：

docker info

在输出里找「Registry Mirrors」一段，能看到上面配的地址就成了。再跑一次 docker run hello-world，明显比以前快。

我试过的：

  • 多写几个地址是有意的：Docker 会按顺序尝试，某个失效了自动 fallback 到下一个。镜像站生命周期短，别只配一个。
  • 这些老地址已失效，看到老教程请跳过：docker.mirrors.ustc.edu.cn（中科大）、mirror.baidubce.com、registry.docker-cn.com（官方中国区早已关停）、docker.nju.edu.cn。
  • 云厂商的专属加速仅限自家云服务器（如阿里云 ECS、腾讯云 CVM），本地电脑用不了，别照抄。
  • 临时单次换源：不想改全局配置时，可以给 pull 命令加前缀，例如 docker pull docker.m.daocloud.io/library/nginx:latest（注意官方镜像要加 library/），拉完用 docker tag 改回原名。适合偶尔拉一个镜像。
  • 合规提醒：生产环境别用来路不明的第三方镜像站，可能有供应链风险；公司环境优先用云厂商内网加速地址。

06 ｜ 跑通第一个容器：hello-world
#

🟡 方案整理 · 待实机验证

为什么：这是 Docker 世界的"开机自检"。跑通它，说明拉镜像、启动容器、终端通信整条链路都正常。

照抄：

打开任意终端（PowerShell / CMD 都行），执行：

docker run hello-world

第一次会从镜像源下载一个小镜像，然后启动容器，打印一段以 “Hello from Docker!” 开头的说明文字。

算完成：看到 “Hello from Docker!” 就全通了。

我试过的：

  • 这条命令做了三件事：找本地有没有 hello-world 镜像 → 没有就去镜像源拉 → 拉下来跑起来。以后再跑就直接从本地启动，秒出。
  • 提示 Cannot connect to the Docker daemon：多半是 Docker Desktop 还没完全启动，等十几秒重试；或确认托盘小鲸鱼图标是稳定的。
  • 想试试真东西：docker run -d -p 8080:80 nginx，然后浏览器打开 http://localhost:8080，能看到 Nginx 欢迎页——你就跑起一个网页服务器了。-d 是后台运行，-p 8080:80 是把容器里的 80 端口映射到本机 8080。

07 ｜ 常用命令速查
#

🟡 方案整理 · 待实机验证

为什么：日常 90% 的时间就用这几条，收藏这一节足够。

照抄（命令表）：

想干嘛命令
看版本docker --version
拉镜像docker pull 镜像名
看本地镜像docker images
跑容器docker run 镜像名
后台跑 + 映射端口docker run -d -p 8080:80 镜像名
看运行中的容器docker ps
看所有容器（含停止的）docker ps -a
进容器内部docker exec -it 容器名 sh
看日志docker logs 容器名
停容器docker stop 容器名
删容器docker rm 容器名
删镜像docker rmi 镜像名
一键起一整套服务docker compose up -d（在有 docker-compose.yml 的目录）
清理无用资源docker system prune（谨慎，会删停止的容器和悬空镜像）

算完成：能自己拉一个镜像、跑起来、看日志、停掉，这一套走完就算入门了。

我试过的：

  • 容器名不记得就用 docker ps 看，或给 run 加 --name 名字 自己命名，好记。
  • docker system prune 会删掉没在跑的容器，重要数据别只放在容器里——用「数据卷 volume」或「目录挂载 -v」把数据存到宿主机，容器删了数据还在。这是新手最容易丢数据的地方。
  • Windows 上项目文件如果放在 C:\Users 下用 -v 挂载给容器，读写会很慢（WSL2 跨文件系统开销）。把项目放到 WSL 的 Linux 目录（如 \\wsl.localhost\Ubuntu\home\你\项目）会快很多。

08 ｜ 图形界面能做什么
#

🟡 方案整理 · 待实机验证

为什么：Docker Desktop 不只是个后台服务，它带图形界面，不想敲命令的人用它也能干活。

照抄（认识界面）：

打开 Docker Desktop 主界面，左边几个页签：

页签能干嘛
Containers看所有容器，点进去能看日志、进终端、启停、删除
Images看本地镜像，能拉取、删除、运行
Volumes管理数据卷
Settings → Docker Engine就是配镜像源的那个 JSON 编辑器
Settings → Resources调 CPU / 内存分配，机器配置低就调小点

算完成：在 Containers 页能看到刚才跑的 hello-world 容器，点进去能看到日志。

我试过的：

  • 图形界面适合"看状态、查日志、清理"，日常启动还是命令或 docker compose 更顺手。两者配合用。
  • 机器内存紧张时，在 Settings → Resources 把分给 Docker 的内存从默认调小（比如 2GB），能明显减轻卡顿。

常见问题
#

你会看到这说明怎么办
安装后启动报"虚拟化未启用"BIOS 里没开 VT-x / AMD-V按第 2 卡进 BIOS 开启，重启
docker 提示不是内部命令没重开终端 / PATH 未加载注销重登或重启后重开终端
Cannot connect to the Docker daemon引擎没启动或还在启动等十几秒；确认托盘鲸鱼图标稳定
拉镜像极慢或超时没配镜像源，或源失效按第 5 卡配/换镜像源，docker info 核对
docker info 看不到 Registry MirrorsJSON 写错没生效检查逗号/格式，Apply & Restart 重来
提示授权/订阅相关超出免费范围确认免费资格；否则付费或换 Podman Desktop
容器里数据丢了数据只存在容器里用 volume 或 -v 挂到宿主机
挂载目录后读写很慢WSL2 跨文件系统开销项目移到 WSL 的 ext4 目录内
WSL 安装卡住网络问题wsl --install --web-download 重试

一条龙（重装时按顺序执行）
#

# 1) 确认 WSL2（管理员终端）
wsl --install
# 重启电脑后核对
wsl --version

# 2) winget 装 Docker Desktop
winget install --id Docker.DockerDesktop -e

# 3) 重开终端验证
docker --version

# 4) 配国内镜像：Docker Desktop → Settings → Docker Engine
#    写入第 5 卡的 registry-mirrors JSON → Apply & Restart

# 5) 验证整条链路
docker info          # 看 Registry Mirrors
docker run hello-world

镜像源那段必须手动在界面配（一行命令搞不定），这是重装时唯一要点的几下鼠标。

免费替代方案（无授权 / 大企业可用）
#

🟡 方案整理 · 待实机验证

为什么：Docker Desktop 授权卡人时，这几款完全免费开源，能跑同样的容器镜像。用户是开发者，值得知道后路。

方案平台特点适合谁
Podman DesktopWin / Mac / Linux免费开源、无守护进程、rootless 更安全；命令和 Docker 几乎一样（alias docker=podman）要彻底免费、安全要求高
Rancher DesktopWin / Mac / Linux免费开源，可选容器引擎，自带本地 Kubernetes（k3s）要做 K8s 开发
纯 WSL2 里装 Docker EngineWin不装 Desktop，直接在 Ubuntu 子系统里装 Docker 引擎不想要图形界面、追求轻
OrbStack仅 Mac快、省资源，但个人免费商用付费Mac 用户（Windows 用不了）

我试过的：

  • Podman Desktop 是最接近的免费平替：Windows 上走 WSL2，有图形界面，命令兼容。代价：少数 Compose 写法、依赖 Docker socket 的工具要额外配置。
  • Rancher Desktop 选引擎要注意：想要继续用 docker 命令和 Compose，装时选 Moby 引擎；选 containerd 就得用 nerdctl，两者镜像不通用，别选错。
  • OrbStack 只有 Mac 版，Windows 上不用考虑。
  • 想完全不装桌面软件：在 Ubuntu 篇 装的 Ubuntu 子系统里直接 curl -fsSL https://get.docker.com | sh 装 Docker Engine，命令行一样用，还避开 Desktop 授权——代价是没有图形界面。
